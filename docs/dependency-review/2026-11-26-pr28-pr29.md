# Dependency review: PRs #28 and #29 (2026-11-26)

Public-safe review note; no account, price, or strategy data.

- PR #28 (`step-security/harden-runner` v2.22.4 -> v2.23.0): the workflow pins commit
  `aebdcf6156ab6691adf63218240e476564a1ed4c`, which is the commit object of upstream tag `v2.23.0`.
  The v2.23.0 release adds an opt-in Secure Registry integration and redacts credentials/signatures from
  signed S3 URLs in some agent error logs. The existing `egress-policy: audit` setting is unchanged, so the
  new registry integration is off unless explicitly enabled. No missing piece found in the PR itself.
- PR #29 (`certifi` 2026.10.23 -> 2026.11.20): `requirements.txt` changes, but the offline wheelhouse still
  contains only `certifi-2026.10.23-py3-none-any.whl`. Because workflows install with
  `pip install --no-index --find-links .github/vendor/wheels -r requirements.txt`, the PR is missing the
  matching `certifi-2026.11.20` vendored wheel (and removal/replacement of the superseded wheel if that is
  the repository's convention). The upstream certifi compare has no new certificates in `cacert.pem`; it
  removes five roots: Buypass Class 2 Root CA, Buypass Class 3 Root CA, QuoVadis Root CA 1 G3,
  QuoVadis Root CA 3 G3, and Certigna Root CA. That trust reduction should be an explicit owner decision
  when the missing wheel is added.
